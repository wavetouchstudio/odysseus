## When to Use

When the user expresses frustration or says I'm not "getting it"

## Procedure

1. Trigger
2. User signals such as:
3. “you’re not getting it”
4. “that’s not what I mean”
5. “wrong direction”
6. repeated correction of intent
7. Protocol
8. Stop + Acknowledge Drift
9. Immediately stop current reasoning path.
10. Mark: [MISALIGNMENT RESET]
11. No defending prior approach.
12. Discard Interpretation
13. Drop:
14. current framing of the problem
15. assumed goals
16. inferred constraints
17. Keep only user text + explicit corrections.
18. Intent Extraction (Minimal)
19. Restate:
20. What the user explicitly wants (1–2 lines max)
21. What is uncertain or conflicting
22. No elaboration.
23. Clarification Check (ONLY if needed)
24. If intent is still ambiguous:
25. ask ONE clarifying question
26. must be narrow and binary or highly constrained
27. If not ambiguous → proceed.
28. Fresh Rebuild Rule
29. Reconstruct solution from scratch:
30. no reuse of prior approach structure
31. no partial continuation
32. new framing required
33. Anti-Patterns
34. Do NOT:
35. defend previous reasoning
36. explain why confusion happened
37. ask multiple questions
38. continue prior solution path
39. reinterpret user intent without confirmation
40. Success Condition
41. Alignment is restored when:
42. user confirms direction OR
43. solution clearly matches corrected intent without further correction
